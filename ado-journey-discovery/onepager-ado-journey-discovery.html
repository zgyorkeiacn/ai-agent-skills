Table AIn scope

An AC directly covers it, a live story delivers it, or it is a logical implication of an AC — "all four SKUs" becomes one row per SKU.

Table BDeferred

The covering story is Removed or Deferred, the ACs use deferral language ("future PI", "TBD"), or no AC covers the row at all — tagged "No AC found". This is the conservative default.

Table COut of scope

Explicitly excluded, matched against the epic's own out-of-scope list, or the covering story is Rejected. The stated reason is printed in the row.

The default is a row, never silence. A candidate with no AC and no exclusion reason cannot be quietly dropped — and Sno runs as one continuous sequence across all three tables, so the set is provably complete.

No counts shown: row volume is set by the epic's real scope, and the skill refuses to pad or truncate to a round number. Read-only by design — the PAT needs only Work Items (Read).

What A Read-Through Misses and this does not

✓

It cross-multiplies to find the silence. Every plan is checked against every add-on, bundle and discount found. Any combination the ACs neither confirm nor deny becomes a logged gap — "12-month FWA plan + TV add-on: no AC addresses this".

✓

Absence itself is a finding. A broadband epic that never mentions a TV add-on anywhere gets that silence raised as a question, rather than being read as "not applicable".

→

It reads the implication, not just the sentence. An AC saying "the 12-month plan appears first for student routes" proves a non-student route exists too — so both are enumerated, even though only one was written down.

→

Memory that compounds across epics. A vocabulary accumulates every plan, flag, voucher and bug, tagging each recurring or new. Anything known from a prior epic but silent in this one becomes a gap citing its source epic.

→

Edge cases become reusable templates. Net-new scenarios are abstracted into placeholder templates with trigger conditions, so the next epic with a voucher and a discount automatically re-enumerates the same bug-zone permutations.

−

Withdrawn text is not evidence. Struck-through content in ADO descriptions and ACs is stripped before analysis, so retracted requirements never leak into the scenario set.

14 non-negotiable rules · PAT never echoed

1It finds everything first

  • Walks relations[] for children, related and dependency links, then runs a recursive WIQL query to catch stragglers the tree missed.
  • Breadth-first to 4 levels deep, batching up to 200 IDs per call; a 404 or 401 on one item logs a warning and never halts the run.
  • Descriptions and ACs are de-HTMLed, entity-decoded and withdrawn text removed before a word is analysed.

2Nothing gets dropped

  • Three classification rules run in priority order, first match wins — out-of-scope, then in-scope, then deferred.
  • Ambiguous evidence resolves to Table B, never Table A. The tool will not promote a guess into "in scope".
  • Every row in Table B and C carries its own reason in the Variation column, so no classification is unexplained.
  • Row counts are never padded or truncated to look tidy.

3Memory across epics

  • One vocabulary per org and project, checked for org/project mismatch before it is trusted.
  • Additive by rule: absence in a new epic means "not mentioned here", never "no longer true" — entries are never deleted, only mutable fields refreshed.
  • Recurring entities get a cross-epic anchor: "In epic X this behaved as Y — does the same apply here?"
  • Managed with vocab show, clear and rebuild; any run can opt out via --no-vocab.

4Questions you can send

  • Seven themed categories — bundles, plan ordering, discounts, out-of-scope rationale, open bugs, coverage gaps, analytics.
  • A category is omitted entirely when the epic has no matching entities. No empty headers, no filler.
  • Every question names the real plan, bug ID, flag or segment. The skill defines a question containing "the plan" as a defect in its own output.
  • Each one is answerable in a single factual reply — no compound questions.
Conservative by construction — that is what makes it usable. The output is an argument you can audit, not a verdict you must trust: every row states why it landed where it did, ambiguity always falls to Deferred rather than being talked up into scope, and unresolved gaps become named questions instead of being smoothed over. It reads ADO only — no code, no tests, no Figma — so the map reflects what the business wrote down, and the questions cover what it did not.
