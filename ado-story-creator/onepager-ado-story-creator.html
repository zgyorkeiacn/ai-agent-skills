Everything You Don't Do By Hand and what it refuses to fake

✓

Acceptance criteria that are actually testable. Every AC is Given/When/Then and at least one per story is a negative case — invalid input, service down, limit exceeded. "The feature works correctly" is explicitly banned.

✓

It marks which ACs it invented. Criteria evidenced in your document are flagged derived; gap-filling inferences are flagged as generated — so refinement knows what to scrutinise.

→

Sprint planning that respects reality. Dependent stories cluster, sort so prerequisites land earlier, then pack against backend/frontend/testing velocity. What will not fit is shown as Overflow, never crammed in.

→

Dependencies inferred by rule. Auth before protected endpoints, create before edit, backend before its paired frontend, schema before the APIs using it.

→

Titles and sizing a PO can read. Verb-object, present tense, 5–12 words — never a bare noun like "Bastion Integration". A 13-pointer arrives with "split this before committing".

→

Three ways in, one shape out. A spec or LLD, a plan-on-a-page, or a git branch diff — reading .docx, .xlsx, .md, .txt and Gherkin .feature directly, no conversion step.

−

It never touches what exists. Only new items are created — no existing story, AC or estimate is modified. A strong first draft for refinement, not a replacement for it.

The Differentiator

Guard Rails & Auto-Correction — it checks your board, then fixes its own mistakes

14 non-negotiable rules · PAT never echoed

1Nothing without consent

  • The preview gate is absolute: the full hierarchy, points, states, lanes and sprints are printed before any write call. No exceptions.
  • Four choices: create all, plan sprints first, pick stories by number, or cancel outright.
  • Your PAT is never printed, logged or echoed — not even in intermediate steps.
CREATE ALLSPRINT FIRST SELECT 1,3,5CANCEL

2It reads your board

  • Swimlanes are fetched from your board and used verbatim — the field is case- and whitespace-sensitive, so typed text is never trusted.
  • Ready for Development resolves to whatever state your board maps it to, not a hardcoded guess.
  • Sprints come from the project iteration tree, deliberately not team settings — those go stale.
  • State is set before lane; ADO silently drops the lane otherwise.

3It repairs its own writes

  • A 400 "field is Required" is recoverable: it extracts the field name, queries your area for a valid value, and retries.
  • One value found → applied silently. Several → it asks you once for all items.
  • If the org rejects the batch API it falls back to sequential creation, rebuilding the hierarchy item by item and re-linking as it goes.
  • Only a failed retry skips an item — and it prints the raw ADO error so you can fix and re-run.

4Quality gates you can't skip

  • Fibonacci only — 1, 2, 3, 5, 8, 13. Never 4, 6, 7 or 9–12, so estimates stay comparable across teams.
  • Three-dot git diff (base...HEAD) — only what the branch introduced, not unrelated commits since the fork.
  • Long documents are summarised heading-by-heading, keeping requirement statements and dropping prose.
  • Dependency cycles are broken before the preview, with a warning naming each removed edge.
It is built to be doubted — that is the point. The preview gate means the worst outcome of a bad run is wasted reading, never a polluted backlog. Inferred acceptance criteria are labelled as inferred, so nobody mistakes a generated guess for a signed-off requirement. Overflow is surfaced rather than force-fitted, and existing work items are never modified. Every judgement it makes is shown to you, attributed, and reversible before a single item is created.
