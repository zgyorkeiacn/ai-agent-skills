CODINGfix production

A wrong result on valid, in-contract input; a symbol that genuinely exists nowhere; a real logic bug. Edit the production file — never the test. And never fabricate a module just to satisfy an assertion.

TESTfix the test

The assertion is wrong or over-specified, or a mock's path, export, signature or data shape does not match reality. Edit the test — never reword production to satisfy a matcher.

The invariant test decides the hard ones. Does the codebase actually guarantee the precondition that makes the code correct? If it does, a fixture violating it is a TEST bug. If the code breaks on input its own collaborators can legitimately produce — like a loader returning [] before init — it is CODING.

No accuracy or throughput figures are shown: the skill publishes none, and inventing them would undercut the point. A TEST verdict can still carry a CODING gap — if the test cites an acceptance criterion that genuinely is not implemented, that part is reported separately. check mode writes nothing at all.

The Traps It Catches and why "just go green" is dangerous

✓

The [].every() trap — a real catalogued defect. A test asserted a zero-activity user had no achievements; it received ["all_complete"]. Because [].every(…) is vacuously true and the loader legitimately returns [] before init, every brand-new user was awarded the "completed everything" badge. Verdict: CODING. Editing the test to expect the badge would have enshrined that bug permanently.

→

Wording drift is a test bug, not a product bug. The error says "timed out", the matcher wants /timeout/ — that is an over-specified assertion. Relax the matcher; do not reword production. Unless the spec mandates the exact string, in which case the wording is the contract.

→

Mocks that drifted from reality. anthropic vs @anthropic-ai/sdk; mockResolvedValue on a synchronous function; a flat fixture where the code reads an envelope. It reads the real collaborator behind every mock to tell drift from defect.

→

Tests that assume an architecture you never built. A test expecting a separate router where the route is inline is retargeted — not answered by inventing the router.

−

Plausible is upgraded to confirmed. Where it is cheap, a throwaway non-destructive repro proves both the failure and that the proposed fix removes it. No source in the repo? It classifies from the log and says the confidence is reduced.

The Differentiator

Correct Attribution — the verdict fixes the blast radius before anything is edited

7 non-negotiable rules · terse, evidence-led output

1Evidence before verdict

  • Reads the exact assertion named in the log — never a guess — plus its fixtures, mocks and beforeEach.
  • Resolves imports against the real repo and reads the genuine collaborator behind each mock: path, exports, sync/async, shape.
  • Walks the failing path from input to asserted output, naming the value that produced the error.
  • Notes both stack frames — test-side and deepest code-side — and resolves the owning package in a monorepo.
CODINGTEST TEST (LESSONS LEARNED)

2Two decisive rules

  • The invariant test: if the codebase guarantees the precondition, a fixture breaking it is the test's fault; if a collaborator can legitimately produce that input, the code must handle it.
  • Semantic equivalence: when the only discrepancy is phrasing, it is over-specification — relax the matcher.
  • The exception is explicit: if a spec or AC mandates the exact string, that wording is part of the contract and the code is at fault.

3Blast radius is fixed

  • CODING → production file only. The test is never edited to conceal a real defect.
  • TEST → test file only. Production code and its error wording are never bent to satisfy an arbitrary assertion.
  • Always the smallest change that resolves the root cause, following the repo's own conventions.
  • Repros are non-destructive: scratch locations, and any real data file is backed up and restored byte-for-byte.

4A catalogue that compounds

  • CODING only, append-only. Real defects accumulate into a durable, reviewable record of what actually broke.
  • It reads the catalogue first — to take the next entry number and to avoid duplicating the same test+error.
  • Portable: it adopts an existing or legacy log before creating a new one, so the record never fragments.
  • TEST verdicts are excluded, except an instructive trap kept and visibly marked "lessons learned".
It is allowed to tell you the test was right — that is the whole value. Anything pointed at a red test will find some way to make it green, and the cheapest route is editing the assertion — which is exactly how a real defect becomes permanent. This inverts the incentive: the verdict comes first, with its justification, and only then is one side touched. Ambiguity is settled by the invariant test on evidence, missing source is reported as reduced confidence rather than a confident guess, and check writes nothing. A green suite is the by-product; correct blame is the deliverable.
